# Neon → PWA Content Sync

تم توحيد مزامنة المحتوى بين Neon PostgreSQL وPWA مع الحفاظ على اللعب الأوفلاين واستقرار جلسات اللعب.

## نظرة عامة
- **المصدر المعتمد**: Neon (فرع التطوير `br-calm-art-b9yzd3hg` فقط). الإنتاج غير مُستخدم.
- **ذاكرة التخزين**: IndexedDB (`qa3da-content`) مع نسخة واحدة لكل مجموعة محتوى.
- **الـFallback**: ملفات `contents/*.ts` المستخدمة عند عدم وجود كاش صالح.
- **استقرار الجلسة**: كل جلسة تستخدم لقطة ثابتة من المحتوى، وأي تحديث في الخلفية لا يغير الأسئلة أو الترتيب في الجلسة النشطة.

## مجموعات المحتوى
`casino`, `topics`, `challenges`, `sheikh`, `zad`, `punishments` (مُخزّن محليًا).

## نقاط النهاية (API)
- `GET /api/content/versions` — إصدارات المجموعات من قاعدة البيانات (DB-sourced، `no-store`)
- `GET /api/content/sets/[id]` — محتوى المجموعة مرتّب بـ`position`، يتضمن `version`، `no-store`. يعيد `400` للـID غير معروف، `404` للمفقود/غير قابل للتشغيل

## سلوك المزامنة
- **Triggers**: عند بدء التطبيق، عند استعادة الرؤية، عند استعادة الاتصال
- **ذكي**: يُحمّل فقط المجموعات التي اختلف إصدارها عن الكاش
- **آمن**: التحقق من البيانات قبل الاستبدال، عدم إتلاف آخر كاش صالح عند الفشل
- **متسامح**: أخطاء الشبكة/٥٠٠ تعاد المحاولة (مع backoff)، أخطاء ٤٠٠/JSON غير صالح تعتبر دائمة
- **غير معيق**: لا يعيق أول عرض أو اللعب النشط

## Service Worker
قانون `NetworkOnly` مُضاف مسبقًا لـ`/api/content/` قبل `defaultCache` لضمان عدم تخزين أخطاء API كـمحتوى.

## فحص المحتوى
```bash
pnpm content:test   # اختبار شامل للمزامنة
pnpm content:verify # التحقق من تطابق DB مع bundled (يتطلب DATABASE_URL)
```
