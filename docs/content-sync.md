# Neon → PWA Content Sync

تم توحيد مزامنة المحتوى بين Neon PostgreSQL وPWA مع الحفاظ على اللعب الأوفلاين
واستقرار جلسات اللعب.

## نظرة عامة

- **المصدر المعتمد**: Neon (فرع التطوير `br-calm-art-b9yzd3hg` فقط). الإنتاج غير
  مُستخدم.
- **ذاكرة التخزين**: IndexedDB (`qa3da-content`) مع نسخة واحدة لكل مجموعة محتوى.
- **الـFallback**: ملفات `contents/*.ts` المستخدمة عند عدم وجود كاش صالح. أي
  مجموعة موجودة في Neon وليس لها ملف محلي بترجع snapshot فاضي بأمان.
- **الـBaseline**: ملفات `contents/*.ts` هي baseline الاستيراد/الإصدار (3,248
  إجماليًا بعد إضافة Bomb في 2026-10-23؛ منها 1,094 للكازينو عند استيراد
  2026-10-21)، وليست مرآة live لقاعدة البيانات. إضافات/تعديلات/حذف الداشبورد
  بتظهر كـ drift متوقع.
- **استقرار الجلسة**: كل جلسة تستخدم لقطة ثابتة من المحتوى، وأي تحديث في الخلفية
  لا يغير الأسئلة أو الترتيب في الجلسة النشطة.

## مجموعات المحتوى

`casino`, `bomb`, `topics`, `challenges`, `sheikh`, `zad`, `punishments`
(مُخزّن محليًا في `contents/*.ts`).

القائمة الفعلية بتيجي من `content_sets` في Neon، مش من قائمة ثابتة في الكود. أي
مجموعة جديدة بمعرّف صالح بتظهر تلقائيًا في:

- `/api/content/versions` و`/api/content/sets/[id]`،
- قوائم ونسخ وإحصاءات `/admin`,
- شاشة اختيار المجموعة في `/admin/questions`.

لو المجموعة مش معروفة في `features/admin/lib/content-sets.ts`، الداشبورد بيستخدم
اسمها من `content_sets.name` وبيانات وصفية محايدة (من غير ما يكسر الصفحة). ألوان
المجموعات المعروفة في `features/admin/constants.ts` وليها fallback محايد.

## نقاط النهاية (API)

- `GET /api/content/versions` — إصدارات كل المجموعات من قاعدة البيانات
  (DB-sourced، `no-store`).
- `GET /api/content/sets/[id]` — محتوى المجموعة مرتّب بـ`position`، يتضمن
  `version`، `no-store`. يعيد `400` لو المعرّف غير صالح الشكل، و`404` لو المجموعة
  غير مسجّلة أو مفيش فيها محتوى صالح للعب.

## سلوك المزامنة

- **Triggers**: عند بدء التطبيق، عند استعادة الرؤية، عند استعادة الاتصال.
- **ذكي**: يُحمّل فقط المجموعات التي اختلف إصدارها عن الكاش، أو الناقصة محليًا.
- **آمن**: التحقق من البيانات قبل الاستبدال، وعدم إتلاف آخر كاش صالح عند الفشل.
- **متسامح**: أخطاء الشبكة/٥٠٠ تعاد المحاولة (مع backoff)، وأخطاء ٤٠٠/JSON غير
  صالح تعتبر دائمة.
- **غير معيق**: لا يعيق أول عرض أو اللعب النشط. اللعبة بتستنى قراءة الكاش مرة
  واحدة بس قبل بناء الـdeck، وبعدها الـsnapshot بيفضل ثابت.

## Service Worker

قاعدة `NetworkOnly` مُضافة مسبقًا لـ`/api/content/` قبل `defaultCache` لضمان عدم
تخزين أخطاء API كـمحتوى.

## Bomb

- الأسئلة في مجموعة `bomb` داخل Neon، و`contents/bomb.ts` هو fallback الأوفلاين
  (67 سؤالًا).
- فئة السؤال لازم تكون واحدة من فئات محرك القنبلة المعروفة؛ السيرفر والداشبورد
  بيرفضوا أي فئة تانية.
- محرك القنبلة بياخد snapshot المحتوى كـparameter، وبيتجاهل أي فئة غير معروفة
  دفاعيًا.
- إضافة/تعديل/حذف سؤال بيزوّد `content_sets.version`، والعميل بيسحب النسخة
  الجديدة في الجلسة الجديدة.

## فحص المحتوى

```bash
pnpm content:test
pnpm content:verify
pnpm content:verify -- --strict
pnpm content:verify:test
pnpm test:registry
pnpm content:bomb
```

- `pnpm content:test` — اختبار شامل لدورة المزامنة والكاش، بما في ذلك اكتشاف
  مجموعة جديدة من `/versions` من غير تعديل قائمة ثابتة.
- `pnpm content:verify` — فحص قراءة فقط لقاعدة Neon. يقارن live مع baseline
  بواسطة `external_id` ويطبع `extra` / `missing` / `changed`. الـ drift المتوقع
  (إضافات/تعديلات/حذف ناعم) لا يفشل الفحص؛ الفشل للسلامة فقط: مجموعة ناقصة أو
  فارغة، صف غير صالح، تكرار `external_id` أو `position`، فراغ `position` غير
  مفسّر، أو baseline id مفقود بلا سجل soft-deleted.
- `pnpm content:verify -- --strict` — نفس الفحص، لكن يفشل عند أي drift (مفيد
  قبل إصدار يضمن تطابق baseline).
- `pnpm content:verify:test` — اختبارات fixtures لقواعد المقارنة والسلامة، بدون
  قاعدة بيانات.
- `pnpm test:registry` — اختبارات المعرّفات الديناميكية وfallback الـmetadata
  وقيد فئات القنبلة.
- `pnpm content:bomb` — خطة قراءة فقط لمطابقة مجموعة Bomb مع المصدر المحلي على
  فرع التطوير. أضف `-- --apply` لتنفيذ الإدخالات الناقصة في transaction واحد.
  السكربت بيرفض أي فرع غير `br-calm-art-b9yzd3hg`، ومش بيعدّل أو يحذف صفوف
  موجودة، وبيتوقف لو فيه تعارض `position`.

- أخطاء الاتصال/القراءة تُبلّغ كفشل تشغيلي (exit 2) منفصل عن فشل سلامة المحتوى.
