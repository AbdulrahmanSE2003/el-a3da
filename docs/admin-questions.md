# إدارة الأسئلة: الإضافة والتعديل والحذف

**النطاق الحالي:** إضافة سؤال جديد، تعديل حقول السؤال المسموحة، وحذف ناعم
(soft delete). لا توجد استعادة من الواجهة، ولا نشر أو مزامنة عملاء.

## من الواجهة

صفحة `/admin/questions` فيها زر **سؤال جديد** في الترويسة، ولكل سؤال ثلاثة
إجراءات:

| الإجراء | النتيجة |
| --- | --- |
| سؤال جديد | يفتح نموذج إضافة للمجموعة المختارة، مع تحقق فوري ثم تحقق سيرفر. |
| عرض | يفتح تفاصيل السؤال، ومنها يمكن الانتقال للتعديل أو الحذف. |
| تعديل | يفتح نموذجًا بحقول السؤال، مع تحقق فوري ثم تحقق سيرفر. |
| حذف | يفتح تأكيدًا واضحًا، وبعد التأكيد يتم soft delete. |

بعد نجاح أي عملية، يتم إعادة تحميل بيانات الصفحة الحالية وتحديث صفحات
`/admin` و`/admin/health` حتى تظهر الأرقام والنسخ الجديدة.

## الإضافة

| الحقل | القاعدة |
| --- | --- |
| `external_id` | مطلوب، unique داخل المجموعة، والحد 100 حرف. |
| `position` | بيتحسب تلقائيًا `max(position) + 1` داخل المجموعة (حتى مع وجود صفوف محذوفة ناعمًا). |
| `set_id` | بيتحدد من التاب النشط في الصفحة. |

- الإضافة بتحصل في استعلام واحد بمعاملة `with next_position ... insert ...
  select`، والـtrigger بيزود `content_sets.version`.
- لو `external_id` مستخدم (حتى لو السؤال القديم soft-deleted، لأن قيد
  unique مش بيستثني `deleted_at`)، السيرفر بيرجّع خطأ على نفس الحقل.
- `question-create-dialog.tsx` بيعرض الفئات الموجودة كـ`datalist`، لكن الفئة
  نص حر زي التعديل.

## الحقول القابلة للتعديل

| الحقل | القاعدة |
| --- | --- |
| `text` | مطلوب، يتم trimming، والحد الأقصى 4000 حرف. |
| `category` | مطلوب لكل المجموعات ما عدا `zad`؛ هناك اختياري. الحد 200 حرف. |
| `correct_answer` | مطلوب لـ`casino` فقط. الحد 1000 حرف. |
| `badge_label` | متاح لـ`zad` فقط، واختياري. الحد 200 حرف. |

الحقول غير المناسبة للمجموعة يتم حفظها كـ`null`، حتى لو أرسل العميل قيمة
لها. `external_id` و`position` و`set_id` غير قابلة للتعديل من الواجهة.

## التحقق والأمان

- التحقق موجود في `features/admin/lib/question-form.ts`، ويُستخدم في العميل
  لتجربة أسرع، ثم يُعاد على السيرفر قبل أي كتابة.
- كل server action في `features/admin/server/question-actions.ts` يبدأ
  بـ`requireAdmin()` قبل قراءة أو كتابة أي صف.
- الكتابات نفسها في `features/admin/server/question-mutations.ts`، والملف
  `server-only`.
- قيم الحقول تمرر كـparameterized queries؛ مفيش string interpolation في SQL.
- السيرفر يقرأ `set_id` من قاعدة البيانات، ويستخدمه لتحديد الحقول المسموحة،
  بدل الاعتماد على قيمة من العميل.
- لا يتم إرجاع تفاصيل أخطاء قاعدة البيانات للعميل؛ الرسالة عامة ويتم تسجيل
  الخطأ على السيرفر.
- Server Actions في Next.js بتعمل فحص Origin/Sec-Fetch-Site مدمج، بالإضافة
  إلى جلسة المسؤول والتحقق من الصلاحية.

## الحذف الناعم وversion

الحذف بينفذ:

```sql
update questions
   set deleted_at = now()
 where id = $1
   and deleted_at is null
```

مفيش `DELETE FROM questions`. السجل بيفضل محفوظًا، لكنه يختفي من:

- قائمة الأسئلة النشطة،
- إحصائيات العناصر الحية في الداشبورد.

الـtrigger `questions_bump_content_version` بيزود `content_sets.version` مرة
واحدة مع التعديل الحقيقي أو الـsoft delete. تحديث حقول بنفس قيمها لا يغيّر
الـversion.

## علاقة الداشبورد بصفحات اللعبة

صفحات اللعبة الحالية لسه بتقرأ المحتوى من ملفات `contents/*.ts`، مش من
Neon. لذلك تعديل أو حذف سؤال من الداشبورد بيغيّر بيانات Neon وإحصائيات
الداشبورد فقط، ومش بيغيّر المحتوى المنشور في اللعبة. ربط اللعبة بقراءة
المحتوى من Neon ونشر النسخ للعملاء خارج النطاق الحالي.

## خارج النطاق

- حذف نهائي (hard delete) من الواجهة.
- استعادة سؤال محذوف من الواجهة.
- تعديل `external_id` أو `position` أو نقل السؤال لمجموعة أخرى.
- نشر أو مزامنة `content_sets.version` مع العملاء.
- أي كتابة على `production` أو migrations جديدة.
